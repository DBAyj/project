# AstraOS Agent Instructions

## Current Scope

- This repository is AstraOS, an AI-centric mobile spatial operating-system project.
- The active work is Phase P5 (Spatial UI and System Interaction Framework), based on the formal `astra-os-p4-v0.4.0-alpha.1` release baseline.
- The P1-P4 predecessor history is reconciled and tagged. P5 completion still requires current predecessor regressions and the real P3-P4-P5 service-chain acceptance test.
- P5 is not complete until `make p5-release-gate` passes on the committed branch and again after merge to `develop`.
- P5 permits the independent spatial UI runtime, component/window/layout/focus/input/interaction models, task and notification surfaces, privacy filtering, state persistence, animation coordination, accessibility semantics, Shell integration, schemas, deterministic fixtures, tests, and reports.
- P5 does not permit AI avatars, speech recognition, visual gesture recognition, eye tracking, full AR glasses, multi-user collaboration, an app store, Android compatibility, a third-party SDK, physical projected-keyboard recognition, real phone touch drivers, light-field or volumetric display, a full physics/game engine, or P6 work.
- P1's dual-window controls, privacy denial, safe stop/hide path, system status, audit trace, accessibility behavior, and P4 safe-clear fallback must remain available.

## Platform Direction

- macOS on Apple Silicon is the development host only. All system-core and service designs must target ARM64 Linux LTS.
- Core code and protocols must not bind to AppKit, SwiftUI, macOS services, or `/Users/...` paths.
- Platform adapters own host-specific paths and devices. Qt UI, C++, Rust, and Python services must remain portable to Linux ARM64.

## Engineering Rules

- Codex App performs development operations; do not require routine manual terminal commands from the user.

- Keep architecture changes in `docs/architecture/adr/` before changing a frozen decision.

- Every public interface needs a schema. Error codes use the central registry. Permissions default to deny.

- Every projection object carries a privacy level, which only the policy service may decide.

- Never use `localhost` as an external-access default; multi-network hosts must support an explicit public address.

- Each phase needs real validation evidence and a report. Do not claim completion without it.

- Do not delete user data, other projects, or expand functionality beyond the active phase.

  # 星穹OS：AI原生空间智能手机系统总体设计方案 V0.1

  ## **一、产品定位**

  星穹OS不是另一个模仿iOS或Android的触屏操作系统，而是一套面向AI时代的：

  **AI原生、空间交互、应用弱中心化、隐私本地化的新型移动操作系统。**

  传统手机的基本逻辑是：

  ```text
  用户打开应用 → 寻找功能 → 输入命令 → 获取结果
  ```

  星穹OS的核心逻辑是：

  ```text
  用户表达目标 → AI理解意图 → 调用系统能力和应用服务
  → 在手机屏幕、桌面、墙面或空间界面中呈现结果
  ```

  系统不再以“应用图标”为中心，而以以下三个对象为中心：

  1. **任务 Task**：用户现在准备完成什么。
  2. **空间 Space**：内容应该在哪里呈现。
  3. **智能体 Agent**：由谁理解、规划和执行任务。

  ------

  # **二、核心差异化**

  ## **2.1 AI是系统运行时，而不是普通应用**

  星穹OS中的AI不作为单独的聊天软件存在，而是进入操作系统核心层，成为与窗口管理器、通知系统、文件系统同级的基础服务。

  AI可以获得经过授权的系统能力，例如：

  - 理解语音、文字、图像、手势和环境；
  - 跨应用组织任务；
  - 操作文件、相机、日历、通信和投影设备；
  - 根据用户习惯动态生成操作界面；
  - 将二维应用信息转换为空间卡片或三维场景；
  - 在本地完成敏感数据推理；
  - 在必要时调用云端大模型。

  移动端AI应采用CPU、GPU和NPU异构调度，而不是让全部模型运行在CPU上。现有移动AI平台也普遍采用CPU、GPU、NPU和感知处理器协同的方式，以平衡推理性能、功耗和散热。

  ------

  ## **2.2 从“桌面系统”转向“意图系统”**

  星穹OS取消传统固定桌面，将主界面设计为“动态意图空间”。

  主界面由以下区域构成：

  ```text
  ┌──────────────────────────────────────┐
  │ 环境状态：时间、位置、设备、人员、隐私等级 │
  ├──────────────────────────────────────┤
  │ 当前任务：今天需要完成的主要事项           │
  ├──────────────────────────────────────┤
  │ AI建议：可以直接执行的下一步操作            │
  ├──────────────────────────────────────┤
  │ 活动空间：工作 / 家庭 / 会议 / 出行          │
  ├──────────────────────────────────────┤
  │ 最近对象：文件、联系人、项目、设备、场景      │
  └──────────────────────────────────────┘
  ```

  用户可以直接说：

  - “把今天的会议资料投到桌面上。”
  - “根据刚才的电话生成项目计划。”
  - “把这台设备的内部结构以三维方式显示出来。”
  - “只把可以公开的内容投影出去。”
  - “让客户看到模型，但不要显示内部报价。”

  系统根据意图自动组合文件、应用、AI模型和投影能力。

  ------

  # **三、3D屏外信息投影定义**

  必须明确，“3D屏外投影”存在四种完全不同的技术路线。

  ## **3.1 第一层：表面空间投影**

  这是第一代产品最现实的方案。

  手机内置微型DLP或激光投影模组，将内容投射到：

  - 桌面；
  - 墙面；
  - 幕布；
  - 玻璃；
  - 专用反射板；
  - 半透明投影介质。

  DLP Pico技术已经能够用于小型低功耗移动投影系统，但手机一体化仍要重点解决亮度、功耗、焦距和热量问题。

  系统通过深度摄像头和空间感知模块识别投影表面，自动完成：

  - 梯形校正；
  - 曲面校正；
  - 自动对焦；
  - 色彩补偿；
  - 障碍物避让；
  - 环境亮度适配；
  - 投影区域裁切；
  - 手势触控定位。

  这类方案本质上仍然是向物理表面投影，但可以通过头部追踪和透视校正产生明显的立体视觉效果。

  ### **适用场景**

  - 桌面AI助手；
  - 虚拟键盘；
  - 会议内容展示；
  - 3D模型旋转；
  - 教学演示；
  - 导航地图；
  - 工业设备维修指导；
  - 游戏棋盘；
  - 远程协作白板。

  ------

  ## **3.2 第二层：单观察者动态透视3D**

  系统使用前置摄像头、眼动传感器或毫米波传感器判断主要观察者的位置。

  渲染引擎根据观察者视角实时改变三维画面透视，使用户移动头部时能够看到物体侧面，从而产生“物体位于桌面上方”的视觉错觉。

  其处理流程为：

  ```text
  观察者定位
      ↓
  头部与眼睛姿态估计
      ↓
  计算观察视锥
      ↓
  重新生成3D透视画面
      ↓
  投影几何校正
      ↓
  低延迟输出
  ```

  这种方式可以提供较强的三维感，但需要说明：

  单个普通投影器无法同时向多名用户提供完全独立的左右眼立体视图。

  因此，第一代产品应将其定义为“视角跟踪型空间3D”，而不是宣传成真正的多人裸眼全息。

  ------

  ## **3.3 第三层：光场扩展底座**

  面向多人观看场景，可以设计一个独立的“星穹光场底座”。

  手机负责AI计算和内容生成，底座负责多视角光场显示。

  光场设备可以同时向不同方向输出多个视图，让观察者从不同角度看到三维物体。现有光场显示设备已经能够输出数十到上百个视角，但相关光学模组的体积、成本和功耗仍不适合直接集成进普通手机。

  建议的产品组合为：

  ```text
  星穹手机
     │
     ├── 普通屏幕模式
     ├── 桌面投影模式
     ├── 墙面大屏模式
     └── 光场底座模式
            └── 多人裸眼3D显示
  ```

  ------

  ## **3.4 第四层：真正的空气体积成像**

  通过飞秒激光激发空气中的物质产生发光点，理论上可以直接在空气中形成体积图像。相关研究已经实现小范围空气等离子体图形，但需要高强度激光、复杂光路以及严格的安全控制。

  这条路线暂时存在以下问题：

  - 激光安全风险；
  - 功耗过高；
  - 发光区域较小；
  - 像素数量有限；
  - 噪声与热量问题；
  - 无法在普通手机厚度内实现；
  - 难以满足消费电子安全认证。

  因此应列入实验室研究计划，不应成为首代手机的量产指标。

  # **五、内核技术路线**

  ## **5.1 不建议首代直接从零开发完整微内核**

  完全从零开发手机内核、驱动体系、基带支持、图形栈、电源管理和硬件生态，技术风险极高。

  建议采用“双轨内核战略”。

  ## **产品轨：Linux LTS内核**

  首代系统使用Linux LTS内核，原因包括：

  - ARM64和RISC-V支持成熟；
  - 移动SoC厂商驱动更容易接入；
  - 摄像头、音频、网络和存储生态完整；
  - 可以更快完成硬件原型；
  - 不影响上层构建完全不同于Android的系统。

  Android同样使用Linux内核，但Android的差异主要来自其运行时、应用框架、服务体系和界面层，因此使用Linux内核并不意味着星穹OS必须成为Android分支。Android本身也通过HAL隔离上层框架与厂商硬件实现。

  ## **研究轨：能力型微内核**

  中长期研究自有的AstraCore微内核，或者借鉴能力型微内核架构：

  - 最小内核；
  - 驱动运行在用户态；
  - 服务之间通过消息传递；
  - 所有资源通过能力令牌授权；
  - Linux运行在兼容域或虚拟机中；
  - AI服务和隐私服务运行在高安全域。

  seL4采用能力型访问控制和强隔离机制，可作为安全设计研究参考，但不建议第一阶段直接将其作为完整消费级手机系统底座。

  # **六、AI系统架构**

  ## **6.1 AI中枢：Astra Intelligence Fabric**

  AI中枢由七个核心服务组成。

  ### **1. 多模态上下文总线**

  统一接收：

  - 语音；
  - 屏幕内容；
  - 相机画面；
  - 用户手势；
  - 眼动信息；
  - 设备状态；
  - 地理位置；
  - 空间地图；
  - 应用事件；
  - 可穿戴设备信息。

  任何应用不能直接无限制获取上下文，必须通过能力令牌申请。

  ### **2. 意图解析器**

  将用户输入转换成结构化意图：

  ```json
  {
    "intent": "project_meeting_materials",
    "target_space": "desk",
    "privacy_level": "internal",
    "participants": ["current_room"],
    "required_tools": [
      "file.search",
      "projection.start",
      "presentation.render"
    ]
  }
  ```

  ### **3. 任务规划器**

  把复杂任务拆解成步骤，并支持：

  - 串行执行；
  - 并行执行；
  - 失败重试；
  - 用户确认；
  - 权限申请；
  - 回滚；
  - 中断恢复。

  ### **4. 模型路由器**

  根据任务自动选择：

  - 端侧小模型；
  - 端侧视觉模型；
  - 端侧语音模型；
  - 云端大模型；
  - 企业私有模型；
  - 专业领域模型。

  ### **5. 个人语义记忆**

  用户数据分成四层：

  | **层级**   | **内容**               | **默认保留方式** |
  | ---------- | ---------------------- | ---------------- |
  | 临时上下文 | 当前对话和当前任务     | 任务结束后清理   |
  | 工作记忆   | 当前项目、近期文件     | 本地加密         |
  | 长期偏好   | 常用设置和操作习惯     | 用户可见、可删除 |
  | 敏感保险库 | 身份、财务、健康等数据 | 独立硬件安全域   |

  ### **6. 工具与Skill运行时**

  应用不仅提供界面，还可以向系统注册可调用能力：

  ```text
  日历应用：
  - 查询空闲时间
  - 创建日程
  - 修改日程

  文件应用：
  - 查找文件
  - 读取文件
  - 分享文件

  3D应用：
  - 加载模型
  - 创建空间场景
  - 投影模型
  ```

  AI只能调用用户授权的工具，不能通过自然语言绕过权限。

  ### **7. AI安全网关**

  负责：

  - 提示词注入检测；
  - 敏感内容识别；
  - 外部数据可信度判断；
  - 模型输出过滤；
  - 工具调用审批；
  - 高风险操作二次确认；
  - AI行为审计；
  - 模型包签名验证。

  # **七、空间显示系统**

  ## **7.1 Astra Spatial Engine**

  空间引擎负责维护真实环境与数字内容之间的对应关系。

  核心对象包括：

  ```text
  World
   ├── Room
   │    ├── Surface
   │    ├── SpatialAnchor
   │    ├── User
   │    ├── Device
   │    └── SceneObject
  ```

  系统需要支持：

  - SLAM空间建图；
  - 平面和曲面识别；
  - 空间锚点；
  - 跨会话位置持久化；
  - 环境遮挡；
  - 深度估计；
  - 手部骨骼追踪；
  - 视线与头部追踪；
  - 投影表面识别；
  - 多设备坐标同步。

  OpenXR可以作为星穹OS空间应用接口的重要基础。它提供跨设备XR接口，并正在扩展平面检测、空间锚点和跨会话持久化等空间计算能力。

  ------

  ## **7.2 投影渲染管线**

  ```text
  应用二维界面或三维场景
            ↓
  空间布局计算
            ↓
  主观察者视角计算
            ↓
  深度与遮挡处理
            ↓
  投影表面几何分析
            ↓
  透视和梯形反向畸变
            ↓
  亮度及颜色补偿
            ↓
  隐私内容过滤
            ↓
  投影器输出
  ```

  系统必须将“普通屏幕渲染”和“空间投影渲染”分开。

  传统应用输出的是矩形窗口；空间应用输出的是场景对象：

  ```rust
  SpatialObject {
      anchor: DeskAnchor,
      geometry: Model3D,
      interaction: HandGesture,
      visibility: Public,
      depth_mode: OcclusionEnabled
  }
  ```

  # **八、创新交互设计**

  ## **8.1 空间卡片**

  普通通知可以变成桌面上的空间卡片，例如：

  - 来电显示在手机右侧；
  - 导航箭头投射到桌面；
  - 会议倒计时悬浮在投影区域顶部；
  - 音乐控制器固定在桌面左下角；
  - AI助手以人物、球体或抽象光团形式出现。

  ## **8.2 空间手势**

  基础手势包括：

  | **手势** | **功能**       |
  | -------- | -------------- |
  | 单指点击 | 选择           |
  | 双指捏合 | 缩放           |
  | 手掌拖动 | 移动物体       |
  | 抓取动作 | 拿起空间对象   |
  | 向外抛出 | 投屏或分享     |
  | 手掌遮挡 | 暂停投影       |
  | 双手展开 | 进入全空间模式 |
  | 握拳     | 返回或关闭     |

  ## **8.3 语音与手势组合**

  用户可以指着桌面说：

  “把设备内部结构放在这里。”

  系统将：

  1. 识别指向位置；
  2. 查找对应设备模型；
  3. 生成空间锚点；
  4. 加载三维模型；
  5. 投影到指定区域；
  6. 开启手势旋转和拆解。

  ## **8.4 任务流界面**

  用户不再频繁切换应用。

  例如用户说：

  “帮我安排下周去上海拜访客户。”

  系统直接生成一个任务空间：

  ```text
  上海客户拜访
   ├── 客户资料
   ├── 可用时间
   ├── 交通方案
   ├── 酒店方案
   ├── 预算
   ├── 待确认事项
   └── 最终行程
  ```

  每个模块背后可以由不同应用或服务提供，但用户看到的是一个统一任务。

  # **九、隐私投影系统**

  屏外投影会显著增加信息泄露风险，因此必须建设独立的Projection Privacy Guard。

  ## **9.1 内容分层**

  所有内容必须标记为：

  - 公开；
  - 房间内可见；
  - 指定人员可见；
  - 仅本人可见；
  - 禁止投影。

  ## **9.2 双画面机制**

  手机屏幕和外部投影显示不同内容。

  例如：

  ```text
  手机屏幕：
  客户名称、内部成本、利润率、谈判底价

  外部投影：
  产品名称、公开报价、产品参数、演示模型
  ```

  ## **9.3 环境感知保护**

  系统检测到陌生人员进入投影区域时，可以：

  - 隐藏敏感字段；
  - 模糊文本；
  - 暂停投影；
  - 切换到公共展示模式；
  - 请求用户确认；
  - 自动添加动态水印。

  ## **9.4 摄像检测**

  在符合法律和硬件能力的前提下，检测有人正在拍摄投影内容时，可提示用户或降低敏感内容可见度。

  ------

  # **十、应用生态设计**

  ## **10.1 四类应用**

  ### **原生应用**

  适合系统级、高性能和低延迟场景。

  推荐语言：

  - Rust；
  - C++；
  - Kotlin Native；
  - TypeScript界面层。

  ### **WebAssembly应用**

  作为星穹OS主要跨平台应用形态：

  - 沙箱隔离；
  - 冷启动较快；
  - 适合跨CPU架构；
  - 可限制文件、网络和传感器权限；
  - 能够同时运行在手机、桌面和投影空间。

  ### **Web/PWA应用**

  降低早期生态门槛，使现有网站能够快速进入系统。

  ### **AI Skill**

  AI Skill可以没有传统界面，只向系统提供能力。

  例如“发票识别Skill”：

  ```yaml
  name: invoice-reader
  permissions:
    - camera.read
    - file.read.selected
    - local_ai.vision
  intents:
    - recognize_invoice
    - summarize_invoice
    - export_invoice
  ```

  ------

  ## **10.2 Android应用兼容策略**

  不建议将Android兼容层放入系统核心，否则系统容易退化成Android套壳。

  正确方式是：

  ```text
  星穹原生系统
       │
       └── 隔离的Android兼容虚拟机
               ├── 独立文件空间
               ├── 受控网络
               ├── 映射通知
               ├── 映射摄像头
               └── 禁止直接访问AI长期记忆
  ```

  Android兼容只用于解决早期应用数量不足，不作为长期主生态。

  # **十一、硬件总体方案**

  ## **11.1 星穹X1概念硬件**

  ### **核心计算**

  - ARM64或RISC-V高性能SoC；
  - 独立GPU；
  - 高性能NPU；
  - 安全处理器；
  - 空间计算协处理器SPU；
  - 独立低功耗传感器中枢。

  ### **显示系统**

  - 主OLED屏幕；
  - 顶部或侧边微型投影器；
  - 自动对焦光学模组；
  - 投影方向微调机构；
  - 环境光传感器；
  - 激光安全检测；
  - 距离检测；
  - 镜头遮挡检测。

  ### **空间感知**

  - 广角RGB摄像头；
  - 深度摄像头；
  - ToF传感器；
  - 红外摄像头；
  - 六轴或九轴IMU；
  - 毫米波存在传感器；
  - 可选眼动追踪模块。

  ### **连接**

  - 5G或后续蜂窝网络；
  - Wi-Fi；
  - 蓝牙；
  - UWB；
  - NFC；
  - 卫星短消息选配；
  - USB-C高速接口；
  - 无线投影底座连接。

  ### **电源与散热**

  投影和端侧AI都属于高功耗任务，建议采用：

  - 大容量电池；
  - 双电芯；
  - 大面积均热板；
  - 石墨散热层；
  - 投影独立温控；
  - 投影亮度动态限制；
  - AI与投影联合功耗调度；
  - 外接底座供电模式。

  # **十二、空间投影工作模式**

  ## **模式一：快速展示**

  手机手持，向墙面投影文档、图片或视频。

  ## **模式二：桌面工作站**

  手机放置在支架上，桌面出现：

  - 虚拟键盘；
  - 文件窗口；
  - AI助手；
  - 视频会议；
  - 任务面板。

  ## **模式三：三维模型**

  将产品、建筑、机械、人体、地图等三维模型投影到桌面。

  ## **模式四：空间会议**

  多台星穹设备同步同一个空间坐标系，共同查看和操作模型。

  ## **模式五：AI数字人**

  AI数字人通过投影进行：

  - 讲解；
  - 导览；
  - 教学；
  - 客服；
  - 会议主持；
  - 陪伴交互。

  第一代数字人是投影到桌面或半透明介质上的视觉效果，不宣称是真正空气全息。

  ## **模式六：隐私工作模式**

  敏感信息保留在手机屏幕，公共内容显示在外部投影区域。

  # **十三、操作系统安全架构**

  ## **13.1 零信任能力模型**

  应用安装后默认没有以下权限：

  - 文件访问；
     -摄像头；
  - 麦克风；
  - 位置；
  - 网络；
  - AI记忆；
  - 投影；
  - 联系人；
  - 系统工具调用。

  每项权限都以能力令牌形式授权，并可以限定：

  - 对象；
  - 时间；
     -次数；
  - 空间；
  - 网络范围；
  - 数据敏感级别。

  ## **13.2 组件化隔离**

  系统服务应拆成独立组件，分别运行在沙箱中。

  Fuchsia的组件模型同样强调组件隔离、能力授予和独立更新，可作为模块化系统设计参考。

  ## **13.3 系统更新**

  采用：

  - A/B系统分区；
  - 原子更新；
  - 更新失败自动回滚；
  - 内核、驱动、系统服务分层更新；
  - 模型独立更新；
  - 应用和AI Skill独立更新；
  - 更新包签名；
  - 供应链完整性校验。

  ------

  # **十四、首代MVP范围**

  不应在第一阶段同时开发完整手机、全息硬件、自研芯片和新生态。

  首个可验证版本应是：

  **基于ARM64开发板、外接微型投影器、深度摄像头和自研星穹OS界面的空间AI终端。**

  ## **MVP必须实现**

  1. Linux LTS启动和硬件抽象层；
  2. 自研图形合成器；
  3. AI意图中心；
  4. 本地语音识别；
  5. 本地小模型与云模型路由；
  6. 任务型主界面；
  7. 桌面和墙面检测；
  8. 自动梯形校正；
  9. 投影触控和手势操作；
  10. 3D模型加载；
  11. 单观察者视角跟踪；
  12. 空间卡片；
  13. 手机屏幕与投影双画面；
  14. 投影隐私分级；
  15. WebAssembly应用运行时；
  16. AI Skill注册和调用；
  17. 原子升级与回滚；
  18. 开发者SDK和模拟器。

  ## **MVP暂不实现**

  - 真正空气等离子体成像；
  - 完整自研微内核；
  - 自研蜂窝基带；
  - 自研SoC；
  - 大规模Android应用兼容；
  - 多人完整裸眼光场；
  - 消费级超薄机身；
  - 全球运营商认证。

  # **十六、关键验收指标**

  ## **系统指标**

  - 开机进入主界面不超过目标时间；
  - 系统服务崩溃不影响核心通信；
  - 更新失败能够自动回滚；
  - 应用权限可追踪、可撤销；
  - AI操作具备完整审计记录；
  - 离线情况下保持核心AI能力。

  ## **AI指标**

  - 常用系统意图识别准确率；
  - 工具调用成功率；
  - 高风险操作误执行率；
  - 本地模型首响应延迟；
  - AI任务中断恢复能力；
  - 用户记忆可解释和可删除。

  ## **空间指标**

  - 平面识别成功率；
  - 投影梯形校正误差；
  - 手势定位误差；
  - 空间锚点漂移；
  - 视角追踪延迟；
  - 投影触控延迟；
  - 自动对焦时间；
  - 不同材质表面颜色补偿效果。

  ## **安全指标**

  - 未授权应用无法访问传感器；
  - 未授权AI无法调用系统工具；
  - 敏感信息不会进入公共投影层；
  - 模型和Skill必须签名；
  - 设备丢失后数据可远程锁定；
  - 投影区域出现陌生人时可自动保护。

  # **十七、主要技术风险**

  | **风险**          | **影响**         | **对策**                             |
  | ----------------- | ---------------- | ------------------------------------ |
  | 投影亮度不足      | 白天不可用       | 首代定位室内、使用高增益介质和底座   |
  | 投影耗电过高      | 续航明显下降     | 分级亮度、外接供电、限制持续时间     |
  | 散热压力          | 手机温度过高     | 投影与AI联合调度、均热板和主动底座   |
  | 手势误识别        | 操作体验差       | 视觉、ToF、IMU多传感器融合           |
  | AI误操作          | 数据和业务风险   | 能力令牌、操作预览、风险确认和回滚   |
  | 隐私泄露          | 外部人员看到信息 | 双画面、隐私标签、人员检测           |
  | 应用数量不足      | 用户无法迁移     | WASM、PWA和隔离兼容虚拟机            |
  | 硬件成本过高      | 无法进入大众市场 | 先做开发者版和行业版                 |
  | 生态被Android吸附 | 失去系统独立性   | Android兼容层不进入核心架构          |
  | 夸大全息能力      | 产品信任受损     | 明确区分投影、视角3D、光场和体积成像 |

  ------

  # **十八、建议的商业切入点**

  首代产品不建议直接与iPhone和主流Android手机竞争。

  更合理的定位是：

  **面向工程设计、教育培训、医疗展示、工业运维和商务演示的空间AI移动终端。**

  优先行业包括：

  1. 工业设备维修；
  2. 建筑和工程模型展示；
  3. 医学教学；
  4. 汽车维修；
  5. 产品销售演示；
  6. 智能会议；
  7. 教育课堂；
  8. 应急指挥；
  9. 数字文旅；
  10. 高端个人生产力设备。

  行业版允许设备更厚、成本更高，也更容易证明3D投影和AI任务系统的实际价值。

  # **十九、最终产品形态**

  完整产品体系可以分为四部分：

  ```text
  星穹OS
  ├── 星穹X1空间AI手机
  ├── 星穹Dock光场与供电底座
  ├── 星穹Glass轻量AR眼镜
  └── 星穹Cloud企业智能体平台
  ```

  四者之间共享：

  - 用户身份；
  - AI记忆；
  - 空间锚点；
  - 应用和Skill；
  - 文件和任务；
  - 安全策略；
  - 设备协同协议。

  最终目标不是制造一部“带投影器的手机”，而是建立一个：

  **以AI为操作核心、以现实空间为界面、以手机为计算中枢的新型个人计算平台。**
