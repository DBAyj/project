# P1 Test Design

Confirmed public seams are domain conversions, configuration loading, intent parsing, projection policy and state services, error-registry lookup, audit JSONL output, JSON Schemas, controller integration, QML components, and the application process. Each is tested from its public API with known input/output literals.

The P1.1 release gate runs 11 CTest cases, 4 JSON-Schema contract cases, 9 QML cases, and 4 Python graphics-classification cases. It reruns focused policy, error-registry, configuration, accessibility, Metal, and visible-window checks. The controller integration test generates a fresh 920-record JSONL batch covering 101 start/pause/resume/stop events and one denied event; every record is validated against `audit-event-v1.schema.json`. A dedicated CTest creates the real `ShellController` and the real QML Phone/Projection components, invokes their controls, injects drag and wheel input into `ProjectionScene`, and asserts rotation, zoom, fullscreen `QWindow` visibility, stop, and denial state. QML tests separately cover pointer-event semantics, safe scene visibility, configuration warnings, and accessible metadata. Runtime Metal evidence requires Qt's renderer-interface output, QSG QRhi initialization, a Metal device, and a CAMetalLayer for both windows.

Tests cover allow/deny privacy cases, legal/illegal transitions, Chinese and English intent examples, valid/invalid configuration and contracts, bounded recent tasks, audit parsing, dual-window model propagation, seven end-to-end scenarios, and a 100-cycle state loop. No test is skipped to create a passing result.
